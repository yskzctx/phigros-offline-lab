# Phira 原版 LSPosed 实验模块

**0.1 开发候选，尚未真机验收，功能未齐全。** 作用于已核对的官方 Phira 0.8.2（39）arm64；模块包名 `com.phira.lab.lsp`。不替换、重新签名或打包原版引擎；模块仅包含自己的 Java/C 适配代码。

当前实现：

- 通过音量上键打开浅色面板，下键关闭；普通 Activity 对话框，无需系统悬浮窗权限。
- 调用原版标准 AP 自动游玩。冷启动默认关闭，按开关实时切换。
- 强制实验游玩使用原版离线结算选项，阻止此路径生成上传用的成绩数据；开启自动游玩后使用原版不计成绩标记。宿主网络权限保留，不进行统一断网。
- 使用独立实验存储，首次从原始 data.json 只读复制私人备份，不复制账号、谱面索引到实验状态。通过原版导入器重新导入自制谱、完整资源包；在原版收藏夹/资源包页面管理。
- 自动游玩前记录 `local_records` 及每个已导入谱面的 `record`，冷启动只恢复记录字段，保留本次新导入的谱面和皮肤文件及索引。
- 将实验存档内现有历史记录设为全 AP，或恢复首次修改前的记录；冷启动生效，不操作原始存档。历史备份独立于自动游玩会话备份。

**目标分数、目标准确率、逐音符规则、RKS 编辑尚未接入。** 模块保留原版成绩完整性检查，不修改、补写或取消这些检查。本候选不能称为完整移植修改版全部功能，也不能凭编译通过宣称原版启动、真实结算或上传隔离已经验收。

## 数据位置与恢复

实验目录：`<原版 Context.getFilesDir()>/phira-lab-082/`。其中 `original-data-backup.json` 是首次启动时读取原始 data.json 的私人备份；不要上传。实验 data.json、charts、respacks 等由原版引擎写在独立根目录中。`session-records.json` 是待恢复的实验记录快照。

退出 Phira，在 LSPosed 禁用模块并冷启动，恢复原始数据路径。不要把实验数据覆盖回原版，不要删除或清除原版应用数据。此操作方案仍需设备验证。

## 构建

需要 JDK 17+、Python 3.11+、Android SDK platform 36 / build-tools 36.0.0、NDK 26.3，以及官方 [Xposed API 82 编译依赖](https://api.xposed.info/de/robv/android/xposed/api/82/api-82.jar)。该 API JAR 只用于编译，不打入模块。

以下路径均由构建者提供，签名文件留在源码目录之外：

```text
python build_module.py --sdk <SDK目录> --ndk <NDK目录> --xposed-api <api-82.jar> --keystore <自有签名库> --alias <别名> --password-file <本地密码文件> --out <输出目录>
```

构建脚本当前支持 Windows、Linux；其他主机需调整 NDK host 路径。它只构建模块，不下载或打包 Phira 原版 APK/资源。输出附带 SHA-256；不要提交密码文件、签名库、原版 APK、运行日志或任何私人存档。

`native/profile.h` 来自固定版本原生库的只读分析。Java 入口会校验原版版本、64 位进程与完整原生库 SHA-256；不匹配时拒绝激活。不得把当前地址套到其他 Phira 版本。
